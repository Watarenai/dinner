## 開発ルール

### ドキュメント駆動のフロー

```
1. 要件をドキュメントに書く（docs/requirements.md）
2. 合意する
3. 実装する（index.html）
4. CLAUDE.md を更新する
5. コミット（コード変更 + ドキュメント変更を一緒に）
```

### コード変更時の約束

- **ドキュメントを先に更新**してからコードを書く
- CLAUDE.md の「アーキテクチャ」セクションと実装の乖離を作らない
- 新しい関数・データ構造を追加したら CLAUDE.md の表を更新する
- コミットメッセージは変更内容がわかるように書く

### 保守運用の約束

- 壊れた機能をそのままにしない（動作確認してからコミット）
- 不要なコードは残さない（本番コードはシンプルに保つ）
- ファイル構成を変更したらCLAUDE.mdの「ファイル構成」を更新する
