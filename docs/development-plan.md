# 開発計画書: 食材スロット

## 開発方針

| 方針 | 内容 |
|---|---|
| **ドキュメント駆動** | 要件定義 → 設計 → 実装 の順で進める。ドキュメントを先に書き、合意後にコードを書く |
| **保守運用重視** | コードの可読性を保ち、CLAUDE.mdを常に最新化する。変更時はドキュメントも同時に更新 |
| **MVP** | 最小限の機能で価値を提供する。スコープ外の機能は将来フェーズに回す |

3. **ドキュメント未整備** — 開発ガイドがなかった（CLAUDE.md作成で対応中）

## 開発ルール

### ドキュメント駆動のフロー

```
1. 要件をドキュメントに書く（docs/requirements.md）
2. 合意する
3. 実装する（index.html）
4. CLAUDE.md を更新する
5. コミット（コード変更 + ドキュメント変更を一緒に）
```

### コード変更時の約束

- **ドキュメントを先に更新**してからコードを書く
- CLAUDE.md の「アーキテクチャ」セクションと実装の乖離を作らない
- 新しい関数・データ構造を追加したら CLAUDE.md の表を更新する
- コミットメッセージは変更内容がわかるように書く

### 保守運用の約束

- 壊れた機能をそのままにしない（動作確認してからコミット）
- 不要なコードは残さない（プロトタイプは参考として残すが、本番コードはシンプルに保つ）
- ファイル構成を変更したらCLAUDE.mdの「ファイル構成」を更新する
